## 3. 사이트 주소 설정 (완료)

- 운영 도메인은 **`site.config.json`의 `siteUrl` 한 곳**에서 지정한다. 현재 값은 `null`이다(연결 전). 빌드할 때 `SITE_URL` 환경변수가 있으면 그 값이 우선한다.
- 한글 주소를 적어도 빌드가 ASCII 주소로 바꿔 canonical, og:url, sitemap.xml, robots.txt에 **같은 HTTPS 주소**로 넣는다.
- 사이트맵에는 `scripts/pages.js`에서 `public: true`인 페이지만 들어간다. 이 표시는 공개 검수를 통과했다는 뜻이다. 현재 세 페이지 모두 6차 운영 빌드 검수(91 통과·0 실패)를 통과했다. `public: false`인 페이지는 사이트맵에서 빠지고 noindex를 유지한다.
- 도메인이 지정되지 않으면 운영 빌드가 실패한다. 미리보기 빌드에는 canonical이 없다. 후보 주소는 사이트 소스·설정 어디에도 들어 있지 않다. 이 세 가지는 `tests/unit/build.test.js`가 확인한다.

| 경로 | 검색 제목 |
|---|---|
| `/` | 급여 계산기 모음 \| 정산노트 |
| `/salary-proration` | 월급 일할계산기 — 중도 입사·퇴사 급여 계산 \| 정산노트 |
| `/weekly-holiday-pay` | 주휴수당 계산기 — 주 15시간·변동 근무 판독 \| 정산노트 |

**리허설 결과(배포 아님)**: `SITE_URL=https://급여계산기.kr`로 운영 빌드를 만들어 로컬에서 브라우저 전체 검수를 실행했다. 결과는 통과 91 · 실패 0 · 미확인 3이다(`docs/domain-rehearsal-report.md`). 세 페이지의 canonical·og:url과 sitemap·robots가 모두 `https://xn--989a2xnd520fn5f.kr/…`로 일치했다. 저장소의 `site.config.json`은 `null` 그대로다.

## 4. 현재 호스팅 환경

- **호스팅 없음.** 저장소·작업 환경에 호스팅 설정(CNAME, vercel.json, netlify.toml, wrangler.toml 등), 배포 자격 증명, 기존 공개 주소가 없다(6차 확인과 같음).
- 따라서 "기존 공개 주소 → 새 주소" 이동은 현재 **해당 없음**이다. 나중에 임시 주소(예: 호스팅 기본 주소)를 공개했다면 5-4의 이동 설정을 적용한다.

## 5. 승인 후 연결 절차

### 5-1. 구매 (승인 필요)

1. 등록 직전에 가비아 등에서 다시 검색해 등록 가능 여부와 가격을 확인한다.
2. 급여계산기.kr을 1년 신규 등록한다. 이벤트가 17,600원은 1년 신규에만 적용되며 종료일이 표시되지 않았으므로 결제 시점 금액을 확인한다. 2년차 연장 금액도 결제 전에 확인한다.
3. (선택) 정산노트.kr을 함께 등록한다.

### 5-2. 호스팅에 도메인 추가와 DNS (승인 필요)

호스팅 서비스를 정한 뒤 그 서비스의 "사용자 지정 도메인" 화면에 **ASCII 주소 `xn--989a2xnd520fn5f.kr`**을 추가한다(한글 입력을 받는 곳은 한글로 넣어도 된다). 호스팅이 안내하는 값을 등록기관 DNS에 넣는다. 일반적인 형태는 다음과 같다.

| 이름 | 유형 | 값 | 비고 |
|---|---|---|---|
| `xn--989a2xnd520fn5f.kr` (루트, `@`) | A / AAAA 또는 ALIAS·ANAME | 호스팅이 안내하는 IP 또는 대상 | 루트에는 CNAME을 쓸 수 없음. 호스팅의 네임서버로 위임하는 방식도 가능 |
| `www` | CNAME | 호스팅이 안내하는 대상 | 대표 주소로 301 |
| (호스팅이 요구할 때) | TXT | 소유권 확인 값 | 확인 후 유지 |

- 값은 호스팅마다 다르므로 **호스팅 화면의 안내를 그대로** 사용한다. 이 문서에 임의 IP를 적지 않는다.
- DNS 반영 확인: `dig +short A xn--989a2xnd520fn5f.kr`, `dig +short CNAME www.xn--989a2xnd520fn5f.kr`
- 6차 `docs/deploy.md` 2장의 호스팅 설정(확장자 없는 주소 응답, 끝 슬래시 이동, 404)을 함께 적용한다.

### 5-3. HTTPS

1. 호스팅의 인증서 자동 발급(Let's Encrypt 등)이 **발급 완료** 상태인지 확인한다. 인증서의 이름은 ASCII 주소로 표시된다.
2. `http://` 요청이 `https://`로 이동하는지, 인증서가 루트와 `www` 모두를 포함하는지 확인한다.

   ```bash
   curl -sI http://xn--989a2xnd520fn5f.kr/ | head -3
   ```

### 5-4. 주소 이동 설정 (기존 공개 주소가 생긴 경우에만)

- 규칙: `https://(기존 주소)/:경로` → `https://xn--989a2xnd520fn5f.kr/:경로`, 301, 경로·쿼리 유지
- `www.`와 정산노트.kr도 같은 규칙으로 대표 주소에 이동시킨다.
- 전환 순서: (1) 새 주소에서 3장·5-5 검증을 통과한다 → (2) 이동 규칙을 켠다 → (3) 기존 주소의 몇 경로를 열어 301과 목적지 경로를 확인한다.

### 5-5. 연결 후 검증

1. `site.config.json`의 `siteUrl`을 `"https://급여계산기.kr"`로 바꾸고 커밋한다(빌드가 ASCII 주소로 변환).
2. 운영 빌드와 전체 검수를 실행한다.

   ```bash
   npm run verify:production
   ```

3. `dist/`를 배포한다(`docs/deploy.md` 2장).
4. 공개 주소를 점검한다. 세 페이지의 200 응답, 검색 제목, canonical, noindex 없음, sitemap, robots, 배포 버전을 확인한다.

   ```bash
   node scripts/check-live.js https://급여계산기.kr
   ```

5. 공개 주소에서 브라우저 전체 검수(직접 접속·새로고침, 내부 링크, 두 계산기 사례, 모바일)를 실행한다.

   ```bash
   E2E_BASE_URL=https://급여계산기.kr E2E_PRODUCTION=1 E2E_DIR=dist SITE_URL=https://급여계산기.kr node tests/e2e/run.cjs
   ```

6. 검색 도구에 사이트맵을 제출한다. Google Search Console(도메인 속성은 DNS TXT 확인), 네이버 서치어드바이저(사이트 등록 후 사이트맵 제출)에 `https://xn--989a2xnd520fn5f.kr/sitemap.xml`을 등록한다(콘솔이 한글 주소를 받으면 `https://급여계산기.kr/sitemap.xml`).

### 5-6. 문제 발생 시 복구

- **새 주소에 문제가 생긴 경우**: 기존 공개 주소가 있다면 5-4의 이동 규칙을 끄고 기존 주소로 서비스를 계속한다. `site.config.json`의 `siteUrl`을 이전 값으로 되돌려 다시 빌드·배포해 canonical을 기존 주소로 복원한다.
- **배포 자체의 문제**: `docs/deploy.md` 4장(호스팅 이전 배포로 되돌리기 → 정상 커밋 재빌드)을 따른다.
- **DNS 변경 되돌리기**: 등록기관 DNS에서 변경 전 레코드로 복원한다. 변경 전 레코드는 바꾸기 전에 화면 캡처나 텍스트로 기록해 둔다.
